# Spike: cross-engine deterministic state hash

Question: does the same coglet Wasm module reach identical per-step state hashes on WAMR
(interpreter and AOT) and Wasmtime, with floats? What breaks equality, and which ABI rules
guarantee it? Outcome and proposed rules: [`docs/adr/0003-determinism-rules.md`](../../docs/adr/0003-determinism-rules.md).

## Layout

| Path | What |
|---|---|
| `guest/` | Rust guest (`wasm32-wasip1` cdylib, static buffers, zero imports in the conforming build). `handle(events, step, logical_time, seed) -> hash`. f32/f64 math, `sqrt`, NaN-producing ops, libm-style functions. Cargo features build one counterexample per rule. |
| `host-wasmtime/` | Wasmtime host (`run`), plus the rule tooling: `lint` (R1, R2, R4, R5) and `nancanon` (R3 module transform). |
| `host-wamr/` | C host on WAMR 2.4.6. Interpreter or AOT depending on the file passed. |
| `scripts/build-guests.sh` | Builds `out/conforming.wasm` and `out/ce-*.wasm`. |
| `scripts/run-matrix.sh` | Runs everything, prints the table, fails on any unmet expectation. |
| `scripts/compare.py` | Per-step comparison; shows the first divergent step and lanes. |
| `../../.github/workflows/spike-cross-engine-hash.yml` | CI. Scoped to this directory. |

## Run it locally

```
scripts/build-guests.sh
(cd host-wasmtime && cargo build --release)
cmake -S host-wamr -B host-wamr/build -DCMAKE_BUILD_TYPE=Release -DWAMR_ROOT=/path/to/wasm-micro-runtime   # tag in versions.env
cmake --build host-wamr/build
WC=/path/to/wamrc scripts/run-matrix.sh      # wamrc from the WAMR release of the same tag
```

## What a step is

Each of 1,000 steps gets an event batch (0-16 records of kind, `f32`, `f64`), a logical time and a
seed, generated by `gen_step` (identical splitmix64 code in Rust and C). Roughly 3/8 of the float
inputs are special: quiet and signalling NaNs with payloads, +-inf, -0, subnormals. The guest
applies each record to 32 `f32` and 32 `f64` lanes (sqrt of negatives, 0/0, inf-inf, floor/ceil/
trunc/nearest, promote/demote, sin/cos/exp/ln/pow, fma, copysign), serialises the lanes plus counters
to a 416-byte state blob as raw bits, and returns FNV-1a-64 of the blob. The host also hashes
the blob itself; both columns must match across engines.

## Limits of this evidence

- x86-64 only (one CPU). aarch64 and 32-bit ARM are expected to be worse for NaN payloads and
  fused multiply-add, and are not tested.
- The threads counterexample only shows what the lint catches and that single-thread atomics run
  identically. It does not spawn threads, so scheduler nondeterminism is argued, not measured.
- The interpreter is WAMR's fast interpreter. The classic interpreter and `wamrc` options other
  than defaults were not varied.

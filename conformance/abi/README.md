# ABI conformance data

## State-hash corpus regeneration (ADR-0035)

Run `python spec/tests/generate_runtime_abi.py` to regenerate serving-runtime
ABI timelines using ABI/manifests 1.0 and Git SHA-256 state identities. This
executes the same authored generators in an isolated staging directory; it
never rehashes recorded traces. The serving runtime still pins router 0.1,
so its build provenance (`source_commit`) and debug boundary names remain on
that separate frozen contract. Current manage 2.0 spec-only timeline companions
are generated by `spec/tests/generate_abi.py` and remain under `spec/fixtures`.
Then regenerate executable archive companions by actually executing WAMR:
`cargo run --locked -p coglet-runtime --features native-engine --example generate_archive_companions`.
The archive corpus byte pins in `tests/executable_archive.rs` must be refreshed
from the generated source files; the historical `spec-v0` tag is not changed.

## Reference guest profile: guest-reference

`reference-guests.json` executes the SDK echo/counter on both shared Engine
implementations (native mock closures and actual WAMR Wasm). It uses peer role
`guest-reference` so runtime/journal adapters do not claim guest execution.
Requests pin events, unsigned context inputs, input file snapshots and test host
rejection codes; exact responses assert calls and committed files. Failed steps
must discard both. Cases never supply expected outputs to the implementation.
Rebuild/freshness-check with `sdk/guest-rust/tests/build_reference_cases.py`.
Commands and explicit qualification boundaries: [guest SDK](../../sdk/guest-rust/README.md#proof-boundaries).


[`cases.json`](cases.json) uses the harness timeline envelope: name and steps,
with send, exact expect (within_ms=200) and journal_hash/path assertions. The
adapter uses u32be-length deterministic CBOR framing by default.

## Adapter fixture profile: abi.step

Each case begins with a fresh runtime fixture; further sends in that case retain
its durable outbox/history. `send.operation=abi.step` carries:

- initial_files: pre-boundary path -> hex snapshot;
- manifest: pinned manifest;
- initial_effect_ids, initial_inbox_wakes, initial_timers, initial_llm_requests:
  on the FIRST send only, seed host state exactly as the ABI trace header defines.
  This is setup data, not expected output. Later sends retain actual evolved state
  and must not reset it. Historical-ID cases seed completed IDs with no pending
  requests; fresh-ID controls use empty ledgers. The adapter must independently
  compute conflict/staged returns, never copy guest_script's expected result;
- inputs: trace/coglet/step/time/seed/previous, engine profile, effective budgets,
  grants, batch and authenticated boundary changes;
- guest_script: ordered calls, ordinary file writes (path -> hex), termination
  (committed or aborted), scripted engine usage, and failure when aborted.

This is a data-only script for the **runtime's engine seam**, not an implementation
or guest-language source file. Calls supply operation, argument and the expected
host result; the adapter must check the host actually returned that result, not
use it to override runtime permission checks. Termination/usage describe the
scripted engine outcome; they are not measurements of a particular Wasm engine.
The real runtime and mock runtime adapters must execute the same script through
their engine seam and produce `{journal, state_hash, record_hash}`. Do not simply
return the expected journal. Engine-loader/guest allocation conformance belongs
to the engine suite and guest SDK cases, not this scripted profile.

Expected journal is the full ABI step-record. state_hash asserts the snapshot;
record_hash asserts the journal contents/chain independently. No-effects, action,
timer, async LLM request, logging, wall and compute abort rollback, inbox boundary,
and two-wake LLM reply scenarios are included. No fixture performs a live LLM call.

## Adapter admission profile: abi.admit

[`admission.json`](admission.json) contains real core-Wasm module bytes in
initial_files, a manifest, effective budgets and pending_events. Each case resets
the fixture. The adapter inspects/admits the module through its real loader or
mock loader, **without running abi_alloc or handle**. It reports admitted,
instantiated, handle_calls, effective_memory_pages, pending_events, journal,
record_hash, state_hash and, on refusal, the common error shown in the fixture.
The error message is normalized at this adapter boundary; native engine text is
not compared. instantiated is measured at the engine seam, not inferred from the
error. Reject before allocation when initial or maximum memory exceeds the cap;
never raise effective_memory_pages. Initial=maximum=cap is the positive control.
Both accepted admission and refusal leave pending events and files unchanged,
with journal/record_hash null (no step attempted). The hash assertion targets the
unchanged state_hash, not a nonexistent record. These tiny modules export the
required signatures and unshared memory; the no-op functions are never executed.
Fixture tests inspect the encoded memory limits and expectations; actual loader
conformance remains the harness adapter's responsibility.

## Catalog admission profile: abi.manifest_admit

`manifest-admission.json` checks the operation/resource distinction before
instantiation. Each case starts fresh and supplies a manifest, a trusted catalog
projection (`name`, `events`, `reads`, `actions`, `exclusive`) and a current,
unexpired grant projection (`coglet`, `operations`, `resources`). These are adapter
setup inputs, NOT surface wire messages; expiry/epoch checks are covered by the
surface suite. The adapter independently performs catalog and permission checks
and returns `admitted`, `reason` and `instantiated=false`; no guest runs. `reason`
is null on success, or the normalized admission reason from the test oracle.
The corpus includes a distinct `speech.speak_chunk`/`audio.speaker` positive and
unknown names, wrong kind, missing lease/operation grant and wrong-owner controls.
Regenerate with `python spec/tests/build_manifest_admission.py`; `--check` checks
freshness. `test_manifest_catalog_and_resource_admission` validates both manifest
schemas and the independent semantic oracle against the source vectors. This is
case-data validation, not proof that a runtime adapter implements the profile.

Schema/fixture tests check internal consistency, golden encodings and hashes;
these are **not** a claim that a real runtime has passed the black-box harness.
See [the ABI](../../spec/abi.md) and its [fixture coverage](../../spec/fixtures/abi/README.md).

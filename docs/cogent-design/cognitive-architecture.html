Cogent cognitive architecture#

Part of the cogent design: the coglets that do the cogent's thinking and learning, and how they are wired. None of them is a centre; each runs on some runtime and reaches the others through the router (ADR-0036).

Who talks to whom#

Teal arrows are families of messages between two coglets, with the calls listed beside them. Blue arrows are the manage port, which is separate: a patch going in to a coglet, and logs streaming out of one. The full list is in the table below.

Where everything runs#

One possible placement. The Softmax app runs Face and the coglets for its connected apps, next to their adapters. A Softmax-hosted runtime runs the fast loop, factory, optimizer and memory. Neither is the centre: any of these coglets could run on either runtime, and the router joins them.

FaceCoglet#

The local half of the conversation. It subscribes to the Softmax app's push-to-talk and voice events, controls the floating orb, and talks to the user itself. Voice is transcribed on the user's machine or sent from there straight to the speech provider; it does not pass through Softmax infrastructure.

Not settled: whether the fast loop or the optimizer files tickets with the factory and applies the patches. Both are written below as able to; only one may end up doing it.

FastLoopCoglet#

The cogent's attention. It handles what present coglets send: it responds, or forwards it on. Today that means taking feature requests from Face, checking memory, filing tickets with the factory, applying the patches that come back, and telling Face. It also decides where the cogent is present, and reads the check-ins of the coglets it is not attending to (presence).

FactoryCoglet#

Takes tickets and produces artifacts: a new skill, a changed coglet. It tests its work, for example against a local simulator of the target app, before it reports. It does not apply its own output; it returns a patch and the fast loop or the optimizer applies it. The scheduler that does the work is reached through a factory adapter, so it can be replaced.

Ticket reports#

The Candidate in a finished ticket is what gets applied: its built policy tree becomes the revision of the Patch sent on the target coglet's manage port. It is a filesystem tree hash, not a Git commit.

OptimizerCoglet#

Watches how the fast loop's interactions go, files tickets with the factory to make things better, and patches coglets as needed. It has no messages of its own: it reads through the manage port and files ordinary tickets.

OptimizerCoglet#

  needs       llm.complete, ticket.submit, ticket.replay, memory.write, memory.query
  owns        (nothing)

  provides  memory.result       MemoryResult    addressed
  provides  ticket.receipt      TicketReceipt   addressed
  provides  ticket.update       TicketUpdate    addressed

  calls     ticket.replay       TicketReplay    bound

  calls     memory.query        MemoryQuery     bound

It uses the manage port's tail_log and read_state on the fast loop, and patch on the coglets it is granted.

MemoryCoglet#

The cogent's memory: what it has learned about the user, the apps and what has worked, kept in one place so every coglet of the cogent can read and add to it. Each coglet still keeps its own working state in its own files; this is what is shared. Version 0 matches on tags and keywords and uses no model.

RouterCoglet#

The coglet that holds the cogent together. It knows which runtimes the cogent may use, installs coglets on them, and carries two things between runtimes: messages from one coglet to another, and manage operations such as patch. It also holds the cogent's presence: it delivers what present coglets send to the fast loop at once, holds what absent coglets send until their check-in, and answers presence.get and presence.set (ADR-0036).

It is a coglet like the others: it has a policy, memory and a manage port, so it can be patched and watched the same way. What passes between it and a runtime is listed under Runtime and router.

Messages between two coglets on the same runtime do not go through the router; their runtime delivers them.

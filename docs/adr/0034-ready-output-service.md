# ADR-0034: Ready-output retrieval before optional embedded runtime pumping

- Status: Proposed
- Date: 2026-11-25
- Authors: Coglet native runtime maintainers
- Related PR: owner card `t_01a210fc6cef991b`
- Supersedes / superseded by: none

## Context

The [embedded adapter ABI](../../spec/surface-protocol.md#embedded-runtime-c-abi-ios)
serializes handle access on a non-audio control queue. It defines `recv` as a
poll, including non-dequeuing size queries and short-buffer retries, but leaves
its optional progress work unspecified. Main `aca3e59` performs clock sampling,
`tick`, native/durable `pump_dispatch`, and only then examines its output front.
A size query and the subsequent exact-buffer call each repeat that pump. A
ready health frame can therefore wait behind unrelated guest or durable work.

The Face lane's retained `health-diagnosis24.md` (SHA-256
`06c3462b1f5b253be0237a1520a554579e9acf2cec5819c810d25e6a43ca6031`)
identifies this source-bound counterexample. Its original failed01/failed02
captures lack ABI entry/exit and SDK receipt clocks. Neither this decision nor
its controlled obstruction experiment attributes those historical failures.
The owner card explicitly accepts this fault-model classification route.

## Decision

Specify an **ordering guarantee**, not a hard-real-time total-call guarantee:

1. `recv` validates pointers and the process panic/generation fence, samples the
   established transport clock, then runs existing session `tick` checks.
   Clock rollback, three-second peer inactivity, read expiry/revocation and
   terminal-error delivery retain their existing semantics. In particular, a
   previously queued read is not automatically still eligible for delivery.
2. After that preflight, if a frame is ready, `recv` MUST query/copy that front
   without invoking `pump_dispatch`. This includes health generated by this
   tick and both stages of the caller's size-query/exact-copy sequence. A short
   buffer still retains the frame. There is no frame priority/reordering.
3. Only when no output is ready after preflight MAY `recv` synchronously pump
   native execution, supervisor reads and durable outbox dispatch. It then
   inspects the output. Such an already-entered call is not preemptible by a
   subsequently ready frame or by another call on the same handle.
4. `send` remains synchronous: copy/validate/admit the input, including required
   durable writes, then optional native/durable pumping as today. A queued reply
   does not preempt an entered send. The adapter's independent native off-switch
   never waits for that call; close waits for exclusive handle custody.

### Work and bounds

| Phase | Work permitted | Bound / limitation |
|---|---|---|
| Entry and preflight | Existing pointer/fence checks, transport clock, tick, expiry/authority maintenance, disconnect on failure | Queue/result capacities remain bounded; service-lock acquisition, diagnostics sinks, allocator, durable purge and OS scheduling have no finite wall-time bound here |
| Ready front after preflight | Read length, report size or copy one frame, optionally pop | At most one frame, at most 1,048,576 copied bytes; no guest execution, dispatch pump or extra durable publication on this branch |
| Empty recv progress | Existing supervisor-read/native-engine/durable-outbox pump | Existing budgets and attempt fences apply, but filesystem/lock/engine scheduling is not a total-call wall-time guarantee |
| Send | Existing input admission, required persistence and pump | Frame size is bounded; no new finite total-call wall-time guarantee |

Thus the service-time claim is **zero optional pump invocations ahead of an
eligible ready front**, and bounded copying after preflight. It is NOT that
preflight is wait-free, nor that arbitrary synchronous calls return within one
second or three seconds. A service mutex held by another thread can still delay
clock/tick. Separating all durability/execution from control service would need
another design and qualification; it is not silently introduced here.

Draining a finite existing output queue delays new pump work, not mandatory
expiry/tick work. Sends still pump, and an empty recv still pumps; no new promise
of scheduler fairness under an indefinitely nonempty peer-driven queue is made.

### Safety and diagnostics

Do not return the front before tick: `expire_reads` removes requests whose
exclusive deadline or authority lapsed. Keep ADR-0029 negative native completion,
heard barriers, late-reply tombstones, and no fabricated heard history. Delivery
of a retained act is not fresh authority or physical success; the adapter still
validates its current grants/deadline. No SDK receipt refresh occurs merely
because runtime output is ready. Keep SDK health/read deadlines and native-stop
fences unchanged. Retain ADR-0027 recovery and uncertain-attempt fencing.

Add bounded non-private timing records sufficient to distinguish call entry,
clock/tick, output-ready, pump entry/exit and return. Record monotonic durations
and call sequence IDs, result status and output depth/kind, never frame bytes,
private arguments, text or audio. Retain a fixed-size recent history and first
failure rather than unbounded logging. A test-gated export/capture is acceptable;
qualification must identify whether deployed builds have that instrumentation.
Native clock samples and SDK uptime remain separate domains; pair calibration
samples instead of subtracting unrelated epochs. Adapter FIFO depth remains
unknown unless measured at the adapter.

## Alternatives

- Return an existing front before clock/tick: rejected; queued reads can have
  expired or lost authority, and inactivity/rollback fences must not be waived.
- Increase health/read timeouts or refresh SDK receipt on runtime readiness:
  rejected; hides the obstruction and weakens fail-closed behavior.
- Concurrent recv/close or background execution sharing the handle: rejected;
  changes the ownership contract and introduces custody/recovery races.
- Pump first but reduce the number of guest steps: insufficient; even one guest,
  mutex wait or fsync can consume the remaining health allowance.

## Consequences

No signatures, return codes, wire schemas, guest ABI, frozen fixtures or retry
identity change. The adapter still polls at least once per second and handles
would-block; this is not a readiness barrier. An empty receive or entered send
can still monopolize its serial worker, so this does not establish uninterrupted
surface liveness under arbitrary engine/storage faults. Linux pointer/WAMR
proofs do not establish iOS suspension or physical/acoustic qualification.

This docs-only decision must obtain independent exact-head review and land
through the queue before implementation starts. The implementation and its
qualification remain on the owner card; merging this ADR completes no consumer
acceptance.

## Verification

Implementation must provide real C-entry tests with real WAMR:

- `ready_output_not_obstructed_by_pump`: controlled, explicitly labelled
  source-bound counterexample. Establish a negotiated, open, pre-heard session;
  let tick naturally queue health; latch at the optional pump boundary. On
  unmodified ordering, prove ready health is withheld and the actual SDK host
  reports `protocolViolation("health timeout")` at age >=3,000,000 us before
  heard, without refreshing SDK lastReceived. Observe prompt local native stop,
  no released effect, and exclusive-handle close custody. After repair, query
  and copy the same ready health without entering the obstructed pump, deliver
  it through the actual SDK receive path and observe refreshed lastReceived
  without that timeout. Apply the same SDK oracle to the no-obstruction control.
  Keep a finite cleanup watchdog, release gates unconditionally and join the
  entered call and serial worker before close/stop attestation.
- `ready_health_latency_bounded_under_pump_load`: real guest execution and
  committed-journal evidence, with measured ABI query/copy times and first-failure
  timing. A test latency threshold qualifies that test environment, not hard
  real-time behavior on every device. Include a no-obstruction control.
- Negative authority controls: tick still removes an exact-deadline/expired or
  revoked read; inactivity still disconnects; short-buffer retries do not dequeue;
  panic/stop generations still fence ready output. An empty receive still drives
  progress. Retain existing surface, ADR-0029 expiry and ADR-0027 restart suites.
- Run Swift surface SDK tests on a macOS runner. Keep independent exact-head
  review, required CI and terminal merge proof for the implementation PR.

The injected pump hold proves the conditional defect class, not naturally slow
WAMR, a storage root cause, or historical failed01/failed02 causality. Keep raw
counterexample clocks, build identity and control separate from natural failures.

## Approval

Proposed; independent review and accepting queue merge must be recorded in the
publishing PR and owner card. No implementation or platform acceptance claimed.

# Product-owned Softmax app surface (ADR-0030)

This directory contains product contract/codegen and the mount-scoped native
command registry. The app has initial Settings registrations only: **not** full
app integration, feature approval, UI coverage, grant authority or transport qualification.
No frozen schema is modified. Provision `catalog.v1.json` with
the separately reviewed `catalog.v1.sha256` and explicit local `surface-0.2`.
The artifact stays version **1**; it has no profile field. A deployed trust pin
must be reviewed, never recomputed from untrusted deployment bytes.

## Files and generation

- `softmax-app.cddl`: sole payload source; closed records, finite unions and arrays.
- `softmax-app.schema.json`: exact JSON-equivalent shapes with the **mandatory
  UTF-8 byte-length vocabulary** implemented in `schema_validation.py`.
- `softmax-app.ir.json`, `catalog.v1.json`, `catalog.v1.sha256`: generated local IR,
  exact entry/operation/resource/URI bindings and separately stored SHA256.
- `Sources/SoftmaxAppSurface/Generated/Types.swift`: generated by existing
  `codegen.swift.generate_swift`, not handwritten wire models. The existing
  dependency-free `CBOR.swift` is copied byte-for-byte, checked for drift and
  compiled in this separate product module. The emitter's `SchemaNode` and
  validator are SDK-internal and cannot select product IR by importing built-in
  CogletTypes. No built-in generated bindings are copied. Consumers import
  `SoftmaxAppSurface` and qualify CBOR types where both modules are present.
- `fixtures.json`: generated shape corpus; real Swift, Rust, independent actual
  Ruby CDDL and JSON Schema all consume the same expected cases.

JSON Schema 2020-12 `maxLength` counts Unicode codepoints, not UTF-8 bytes.
Replacing `.size` with it is not equivalent. This schema therefore requires
`minUtf8Bytes`/`maxUtf8Bytes`; use `schema_validation.validator(rule)`. A plain
validator that silently ignores required vocabulary is **not qualified**.
No regex or cross-engine regex dialect is used. Schemas are selected through
`$defs`/catalog URIs; there is deliberately no permissive root payload union.

```sh
uv run --python 3.12 --with-requirements apps/softmax-mac/Surface/requirements.txt python apps/softmax-mac/Surface/generate.py
uv run --python 3.12 --with-requirements apps/softmax-mac/Surface/requirements.txt python apps/softmax-mac/Surface/generate.py --check
# Install the repository's pinned spec/tests/Gemfile.lock Ruby oracle first.
# Set BUNDLE_PATH to that installation if nondefault.
uv run --python 3.12 --with-requirements apps/softmax-mac/Surface/requirements.txt python apps/softmax-mac/Surface/test_surface.py
swift test --package-path apps/softmax-mac/Surface --scratch-path "$TMPDIR/softmax-surface-swift"
cargo run --locked --manifest-path apps/softmax-mac/Surface/runtime-probe/Cargo.toml --target-dir "$TMPDIR/softmax-surface-rust"
```

`generate.py --check` is read-only and compares all seven artifacts, including
codec provenance, fixture bytes, local IR and pin. The runtime probe is an isolated
Cargo workspace, not a new shared test target; its own lockfile is retained.
Swift tests use the actual generic SDK pinned loader and selected validation.

## Finite UI vocabulary provenance

Names are semantic wire ids, not user-visible labels or private storage keys.
Supported window/route pairs are a discriminated union in `app-location`; they
also constrain open window state and view/window events.

| Source (under `apps/softmax-mac/Sources`) | Contract inventory |
| --- | --- |
| `SoftmaxApp/SoftmaxApp.swift` | menu bar, settings, onboarding, Face, chat, orb, HUD, palette, About, quit confirmation |
| `SoftmaxApp/Windows.swift` | all seven Settings tabs; onboarding welcome/permissions/hub; keyboard-shortcuts sheet; appearance System/Light/Dark, text-size standard/large/largest (native 1.0/1.3/1.6), orb, hold/toggle, sound cues, hotkey, login state |
| `SoftmaxApp/OrbOverlay.swift` | chat/voice routes, orb and native orb gestures (registry must register actual commands) |
| `SoftmaxApp/HubSettings.swift` | pairing code/manual sheet and sign-out confirmation; OS-owned QR file chooser is outside app tree |
| `SoftmaxApp/FacePanel.swift`, `SoftmaxCore/FaceDriver.swift` | full/compact mode and six finite expressions |
| `SoftmaxCore/StateMachine.swift`, `SoftmaxApp/TalkHUD.swift` | talk and HUD states |
| `SoftmaxCore/Permissions.swift`, `SoftmaxCore/HubConnection.swift` | login statuses and closed public hub status, no identity diagnostics |

`main/main` is reserved for the ADR's optional main window: the current menu-bar
app has none and must report it closed. It must never fabricate a main window.
All other optional windows are likewise reported closed when unmounted.
The only allowed settings are the seven ADR/UI variants. `launch_at_login`
readback is the real five-state status; requested setter value is boolean.
Hotkeys use bounded native key code plus at most four named modifier choices,
not raw native bitfields. The adapter must reject duplicate modifiers.

## Required adapter semantic checks (not schema claims)

`ControlRegistry.swift` enforces schema/ASCII-id/parent bounds, live route and
visibility/enabled/verb checks, mount incarnation, protected-value redaction
before calling getters, real-focus witnesses, revision-bound pagination and
effect-time host authorization. Registration values use the generated models'
validator, not parallel handwritten wire models. Duplicate ids fail closed;
old unmounts cannot remove successors. The SDK, not this registry, still owns
durable action admission/retry. `SwiftUIRegistration.swift` provides `.coglet`,
`CogletButton` and `CogletToggle` sharing the actual user closure/binding. Native
SwiftUI mount ordering, all-control coverage, revision durability, complete
windows/routes/focus and actual transport custody remain unqualified. The current
app registry's revision seed is in-memory and MUST NOT be exposed as a durable
source incarnation. No adapter has been started for these initial registrations.

Registry unit tests are not the five named native app acceptance proofs.
The required Softmax Mac workflow compiles/tests this product module and the
real Xcode app. Linux tests deliberately exclude the conditional SwiftUI code;
their success cannot qualify the native modifier or its mount-order behavior.

Schemas close payload shapes, not native semantics. The actual registry must
still enforce: unique complete window inventory; existing parent/focus ids;
no cycles/duplicates; at most 4096 registrations and depth 32; per-control finite
selection subset and verb support; mount incarnation/current route/visibility;
protected-control constant redaction before observation; ownership, epoch,
resource, sensitivity and deadline fences. Text/label/id bounds are UTF-8 bytes;
entire wrapper limits must also be checked, returning resource_exhausted.
Revision/cursor mutation and durable-incarnation fences are adapter/runtime work.
Both invoke operations intentionally use the same closed verb schema; only the
separate sensitive binding may mutate protected controls. Schema validity never
confers native authority, especially for launch-at-login approval paths.

No permission, identity, secret or provider configuration is a setting variant.
Open/close/navigate must not bypass protected commands. Secret type_text bytes
remain private action/audit data and must not reappear in events/readbacks.
